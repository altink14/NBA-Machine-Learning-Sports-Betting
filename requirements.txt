# WHY THESE ARE PINNED (2026-09-22). This file had no version constraints at
# all, so `docker build` resolved whatever was newest on the day. Checked: the
# image was installing pandas 3.0.6, numpy 2.4.6, xgboost 3.2.0, scikit-learn
# 1.9.1 and scipy 1.17.1, against a model that was sealed, evaluated and is
# served locally on pandas 2.3.0, numpy 2.3.0, xgboost 3.0.2, scikit-learn
# 1.7.0 and scipy 1.15.3. A major pandas boundary, silently, in production.
#
# To be clear about what was and was not shown: nothing here demonstrates that
# the newer stack produces different predictions. What it demonstrates is that
# production was running a DIFFERENT numerical stack from the one the sealed
# evaluation measured, and that nobody would have found out from a log — the
# build succeeds either way. The 67.2% figure describes the model as evaluated,
# and that claim is only as good as the code underneath it staying put.
#
# The numerical stack is pinned exactly: these decide what the model outputs.
# The web stack has floors and upper bounds instead, because a break there
# fails loudly at boot rather than quietly in a number.
#
# When upgrading the numerical pins: re-run Tests/ (135 tests) and
# preflight_opening_night.py, and check the candidate still produces the same
# probabilities on a fixed slate. Do not bump them casually.
